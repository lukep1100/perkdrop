# Google Play Data safety — draft source worksheet

8 November 2026. Not submitted or certified. Review the final signed Android bundle, all included SDKs and current server behaviour before answering Play Console. Google's collection definition includes off-device transmissions, pseudonymous identifiers and data collected by owned WebViews; internal-only testing has a different disclosure scope from closed testing/production.

| Data area | Evidence and proposed review answer |
| --- | --- |
| Foreground location | `mobile/App.js` requests location only after Near me. Rounded coordinates (three decimals, approximately 100 m) are transmitted to the nearby service; this can still qualify as precise location. Manual-area browsing works without permission. Review service/access-log retention before calling processing ephemeral. No background location. |
| Device/user identifiers | Guest-device credentials and visitor/session identifiers support private saves, passes, pairing and product analytics. These are pseudonymous; do not answer that no identifiers are collected. Review identifiers retained by owned map/detail WebViews too. |
| Product interactions | Search, listing opens, saves, source/directions actions, app first-open and OS/campaign metadata go to the existing tracking service. Review purposes as app functionality and analytics rather than claiming anonymous data is out of scope. Internal build traffic is excluded from public growth reporting. |
| User-provided content | Saves, private plans/notes, listing reports and supported pass requests reach the existing backend. Owned WebViews can expose additional forms; check every reachable form before ruling out names, email addresses, phone numbers or other user-provided content. External provider-browser bookings are separate. |
| Notifications | Initial Play profiles keep remote push disabled. Do not advertise Android notification delivery or declare an active FCM token flow without checking the final bundle/config and opt-in behaviour. |
| Photos/audio/contacts/files | The consumer native app does not need camera, microphone, gallery/media, contacts or broad storage access. Unnecessary permissions are blocked and checked in the actual QA APK. This does not excuse auditing content submitted through any reachable owned-web form. |
| Service providers/sharing | Supabase hosts the catalogue/private guest services. Vercel serves owned web pages/product analytics. OpenStreetMap receives map tile requests; official provider links and directions open when selected. Review processor/user-initiated-transfer exceptions and actual agreements before selecting No sharing. |
| Security and deletion | Current endpoints use HTTPS and server-side owner/device checks. Settings has Delete PerkDrop data with typed confirmation; https://perkdrop.au/delete-account provides the external route. Necessary transaction evidence can be retained without its consumer/device/pass access link. Do not promise deletion of independently held venue bookings. |

Additional Console declarations remain open: actual ads/sponsored placements, adult/parent-directed target audience, IARC content including alcohol-related offers, app access instructions and any restricted-permission questions. No payment-card collection, subscription or native in-app purchase is added by this release preparation.
